## 1. 业务场景与目标

语音识别在专有名词、人名、地名和业务词汇上容易出现错误。业务词表还会持续变化，如果每次新增热词都重新训练完整识别模型，训练成本和更新周期较大。本项目为英语、西语和葡语构建音素热词识别分支，将检索出的候选词作为后续转写的参考信息。

设计目标包括：

1. 热词以词面、语言和音素形式存储，更新词表不要求修改模型权重。
2. 保留Qwen3-ASR-1.7B主体，优先训练轻量CTC分支，降低试验成本。
3. 将音素识别、热词检索和最终转写分别评估，定位实际收益和错误来源。
4. 对错误标签、困难语音和不合理候选保留可解释的诊断记录。

本阶段的模型训练是“冻结编码器、训练CTC Head”，不是完整大模型的全参数微调。在线服务无中断更新和商业部署SLA也不作为本报告已完成的验收结论。

## 2. 总体架构及模型选择

```text
音频
  → Qwen3-ASR-1.7B音频编码器（冻结）
  → ln_post特征，1024维
  → 轻量CTC Head
  → 音素序列及后验信息
  → 音素Anchor候选检索、排序与门控
  → Top-K热词
  → 后续上下文提示与Qwen转写
```

采用既有Qwen音频表示，可先检验其特征能否支持音素识别，避免一开始同时改变编码器和文本解码器。CTC分支负责音素序列和热词检索输入，不承担最终自然语言转写。

编码器已有运行记录确认：1秒音频对应13帧、2秒音频对应26帧，特征维度1024；变长batch保留真实有效长度。冻结音频编码器参数量为317,477,504。编码器特征以bfloat16存储，Head训练使用float32。

对应实现：[音频编码器](../src/qwen_hotword/modeling/audio_encoder.py)、[CTC特征接入](../src/qwen_hotword/modeling/ctc_tap.py)、[Head定义](../src/qwen_hotword/modeling/ctc_head.py)。

## 3. 训练数据与音素标签设计

### 3.1 语料选择

扩量实验固定每语言约480小时训练数据，保持语言级时长平衡，并保留来源差异。

| 语言 | 主要来源与范围 | 训练记录数 | 目标时长 |
|---|---|---:|---:|
| 英语 | Swift美式英语语料 | 340,379 | 约480小时 |
| 西语 | SLR61、Rioplatense、明确拉美元数据的Common Voice及确认拉美范围的Noah语料 | 296,399 | 约480小时 |
| 葡语 | Noah口语、Noah金融、MLS、Common Voice、FLEURS | 321,741 | 约480小时 |
| 合计 | 三语固定清单 | 958,519 | 约1,440小时 |

葡语Noah来源为巴葡；其他葡语来源的口音证据需按元数据分别理解，不能把语言标记`pt`自动当成逐说话人巴葡认证。

训练采用`all_samples_once`，每轮每条样本使用一次，不从较小数据池重复抽样凑时长。训练与验证分离，测试集不参与训练和参数选择。文件身份去重不能发现所有重编码音频或重叠切片；部分来源缺少可信speaker ID，因此不声称所有来源均实现说话人完全隔离。

对应实现：[三语数据冻结](../src/qwen_hotword/training/multilingual_480_freeze.py)、[冲突修复](../src/qwen_hotword/training/multilingual_480_repair.py)、[音频冲突检查](../src/qwen_hotword/training/audio_conflict_audit.py)。

### 3.2 清洗、MFA G2P与标签装配

数据处理流程为：

```text
原始文本及音频索引
  → Unicode及连接符规范化
  → 唯一词表、词频、数字片段统计
  → 对应语言MFA G2P生成发音
  → 字典覆盖与音素词表兼容检查
  → 句级音素和token ID装配
  → 音频信息及CTC可行性检查
  → 可训练记录 / 待复核记录
```

规范化保留影响发音的重音字母，不把所有带重音字符简单替换为ASCII。数字片段单独报告，不在未知上下文中自动猜测读法。连接符是否接受由明确策略控制。字典缺词、多候选发音、未知音素和空标签均保留问题原因，避免静默丢失。

MFA G2P对唯一词表生成发音，再按原句顺序装配标签，减少逐句重复处理。当前使用单个候选发音作为参考，能够形成稳定可复现的标签，但无法穷尽口音、弱读和连读。

已有葡语全量处理记录：366,508条源记录、约496.70小时；初次严格筛选中243,876条、约326.87小时进入可训练集合，其余122,632条进入待复核集合。该数字属于早期单来源构建，不是当前480小时清单的统计。

关键代码：[词表准备](../src/qwen_hotword/training/g2p_prep.py)、[MFA字典审计](../src/qwen_hotword/training/mfa_audit.py)、[标签装配与清单构建](../src/qwen_hotword/training/full_manifest.py)、[西语规则化修复](../src/qwen_hotword/training/spanish_mfa_repair.py)。

### 3.3 音素密度与CTC可行性

设参考音素数为`N`，CTC有效输出帧数为`T_eff`，音素密度为`N / T_eff`。CTC还需要为相邻相同标签提供分隔，因此最短可行长度不仅取决于`N`，还取决于相邻重复标签数量。

`original_ready`表示原时间分辨率下符合相应准入条件的记录；`temporal_2x_recovery`表示通过2倍时间扩展恢复可行性的记录。它们反映的是处理路径和对齐约束，不能直接解释为“干净”和“脏”。最终可行性必须使用提取后的真实有效长度重新检查，不能只相信音频时长估计。

对应实现：[时间分辨率恢复](../src/qwen_hotword/training/temporal_recovery.py)、[实际编码长度检查](../src/qwen_hotword/training/ctc_overfit.py)。

### 3.4 MFA强制对齐的用途和限制

G2P从文字预测发音；强制对齐则在给定文本和发音词典的前提下，为音频分配时间边界。两者用途不同。

100条葡语声学检查记录中，98条产生完整对齐，1条不完整，1条缺少对齐；同时存在词典OOV问题。该结果说明检查链路能够运行，不能解释为98%的参考标签已被证明正确。如果说话人省略某个音素，而标准G2P标签保留了它，强制对齐不一定能独立识别和修复这种差异。

对应实现：[MFA试验准备](../src/qwen_hotword/training/pt_mfa_pilot.py)、[MFA执行与结果分析](../src/qwen_hotword/training/pt_mfa_runner.py)。

## 4. 轻量CTC Head与训练策略

### 4.1 Head结构

当前temporal-2x Head的主要结构为：

```text
LayerNorm
  → 时间维重复扩展2倍
  → 1×1卷积投影到512维
  → GELU与Dropout
  → kernel=5逐通道卷积及上下文投影、残差
  → 音素类别输出层
```

各关键位置根据有效长度屏蔽padding，防止补齐区域通过卷积影响有效音频。2倍扩展增加CTC对齐位置，不等于增加新的声学观测。当前三语配置的Head可训练参数为838,746，远小于冻结音频编码器。

### 4.2 固定优化配置

| 项目 | 配置 |
|---|---|
| 优化器 | AdamW |
| Head | temporal_upsample，hidden=512，kernel=5，dropout=0.1，time factor=2 |
| batch size / 初始学习率 | 256 / 0.0003 |
| weight decay / 梯度裁剪 | 0.0001 / 5 |
| 采样 | 每轮全量样本各一次 |
| checkpoint选择 | 三语等权Macro PER；平局时比较最差语言PER及验证loss |
| 早停 | 最少5轮，patience=6，改善阈值0.001，即0.1个百分点 |
| 学习率调整 | 验证loss驱动，patience=2，factor=0.5，下限0.00001 |
| 训练阶段 | 先5轮检查收敛；后续同状态续训，总预算最多30轮 |

特征先分片缓存，再训练Head，使后续epoch无需重复运行冻结编码器。每片512条，训练按片读取；状态保存Head、优化器、调度器和历史指标，恢复时校验配置一致性。

对应实现：[分片缓存](../src/qwen_hotword/training/feature_cache.py)、[训练器](../src/qwen_hotword/training/sharded_ctc.py)、[训练配置](../configs/480h_training.workzone.json)。

## 5. 热词检索算法

热词统一保存词面、语言和音素表示。Anchor索引用音素片段缩小候选范围，再结合编辑差异和后验信息排序、门控，输出Top-K列表。这样避免对全部词表逐项执行同等成本的细匹配。

本轮wave试验固定每语言4,000个词：

| 语言 | 必留目标并集 | 近音补词 | 旧词表补词 | 合计 |
|---|---:|---:|---:|---:|
| 西语 | 316 | 1,842 | 1,842 | 4,000 |
| 葡语 | 295 | 1,279 | 2,426 | 4,000 |

先保留四个wave的全部目标，再选近音词及补充词。选词不使用本轮模型预测或参考转写。音素相同而词面不同的候选保留，不因为“同音”直接合并；标签序列相同也不等于发音已经得到人工确认。

wave检索固定Anchor ngram为2/3/4、shortlist为64，threshold=0.75、posterior weight=0.25、minimum posterior=0.5、maximum edit ratio=0.35、margin=0。Top5和Top7来自同次计算及固定排序重放，不分别调参。导出格式为音频ID到`[{"word": ..., "phoneme": ...}]`，无候选保留空列表。

对应实现：[Anchor索引](../src/qwen_hotword/hotwords/anchor_index.py)、[评分](../src/qwen_hotword/hotwords/scoring.py)、[词表构建](../src/qwen_hotword/evaluation/wave_keywords.py)、[wave检索](../src/qwen_hotword/inference/wave_retrieval.py)。

## 6. 评估指标与结果

### 6.1 指标定义

| 指标 | 定义与用途 |
|---|---|
| PER | `(替换+删除+插入)/参考音素数`，反映与音素参考标签的差异 |
| Macro PER | 各语言PER等权平均，用于避免音素数量较多的语言独占选模权重 |
| 目标热词Recall | 被选中的正确“目标词×音频”对数/参考中存在的目标对数 |
| 候选干扰比例 | 输出候选中未在规范化参考文本匹配到的比例 |
| WER | 最终转写的词级编辑错误率，需要实际文本解码结果 |

PER、热词Recall和WER具有不同分母，不能互相替代。参考标签不确定性也会影响PER。

### 6.2 葡语历史对照

以下三种Head使用同一2,662条葡语验证样本，便于比较：

| Head/训练方案 | 葡语PER | 结论 |
|---|---:|---|
| 原三语temporal-2x | 9.662% | 历史比较基线 |
| 旧葡语专用Head | 9.032% | 略优，但训练来源和规模不同，不能直接量化为纯多语干扰 |
| 删除recovery、重复抽样original-ready的候选 | 10.285% | 退化0.623个百分点，不替换基线 |

失败候选仅使用约108.52小时唯一葡语，再重复抽样维持记录曝光，不能称为重新精选150小时唯一数据。仅评original-ready时，原三语PER为8.437%，候选仍为8.859%，因此退化不能完全归因于困难验证样本。错误分解显示退化主要来自删除错误。

改进判断：保留有价值的困难样本，先控制标签可靠性、数据唯一性和覆盖范围，再验证扩量效果；不把删除全部recovery作为默认清洗策略。

### 6.3 每语种480小时的阶段结果

固定旧验证集合8,101条，英语2,808条、西语2,631条、葡语2,662条。首5轮结果如下：

| 语言 | 原150小时三语基线PER | 480小时方案第5轮PER |
|---|---:|---:|
| 英语 | 4.736% | 4.6743% |
| 西语 | 3.910% | 4.1053% |
| 葡语 | 9.662% | 9.6391% |

第5轮Macro PER为6.1396%，最佳epoch为5，未触发早停。葡语基本持平，尚未证明扩量带来明显改善。该比较是新方案中间checkpoint与历史最终checkpoint的比较，不是等计算预算的因果实验；每轮音频曝光也已增加。

### 6.4 4,000词wave检索结果

使用原三语Head，四个wave各含100条西语和100条葡语音频，共800条，产生16份Top5/Top7下游文件。

| wave | 西语Top5 Recall | 西语Top7 Recall | 葡语Top5 Recall | 葡语Top7 Recall |
|---|---:|---:|---:|---:|
| 1 | 24.48% | 38.54% | 20.32% | 27.27% |
| 2 | 21.88% | 35.42% | 14.97% | 19.79% |
| 3 | 40.88% | 54.72% | 43.60% | 61.63% |
| 4 | 29.28% | 44.75% | 41.05% | 60.53% |
| 按目标对数汇总 | 28.59% | 42.82% | 29.76% | 41.98% |

汇总分母分别为724和736个目标对。Top7扩大目标覆盖，但输出候选约65%–66%未在参考文本匹配到，需要关注后续提示干扰。本轮未运行文本解码器，不能据此声明最终WER改善。可用纯负样本极少，也不足以可靠估计一般场景的无热词误触发率。

### 6.5 独立端到端与性能记录

历史三语formal100端到端试验每语言100条，C为无检索提示、D为Anchor Top5提示、E为Oracle提示。语言等权WER分别为5.47%、5.04%、4.80%；最终热词命中分别为480/516、489/516、497/516。D的416个错误提示中有102个写入文本，表明提高召回必须同时控制错误候选。

该试验使用threshold=0.86、minimum posterior=0等固定参数，与上述wave试验数据和门控不同，不做直接横向优劣比较。

性能方面，480小时方案特征提取约4.55小时，训练缓存1873片、验证缓存16片，共约139.91GB；首5轮Head训练约69.13分钟。历史端到端D相对C的整句平均推理耗时差约68ms，该值不是纯检索P95，也不能作为服务并发或商业SLA结论。

## 7. 可靠性与后续改进

已实现的可靠性机制包括输入字段约束、异常样本显式分类、真实长度复核、分片完成度检查、恢复配置校验、已有产物防覆盖和按语言报告指标。这些机制提高处理过程的可检查性，不等于消除标签或口音偏差。

后续按证据推进：

1. 完成固定参数训练，比较葡语PER、S/D/I及英西退化情况。
2. 在固定检索资产上区分shortlist漏召、排序与门控损失。
3. 保持同音频对照，独立审计发音变体；多发音标签先试验，不直接全局合并音素。
4. 高密度且标签可靠的样本若持续以删除为主，再单独评估时间分辨率或困难样本权重。
5. 用同批音频比较无提示、Top5和Top7最终转写，确认产品层收益。

本方案已完成数据处理、Head训练和热词检索的可执行链路；现有结果同时揭示了葡语PER和候选干扰问题。最终质量提升仍需以受控实验及下游转写评估确认。
